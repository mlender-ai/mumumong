# MUMUMONG Visual System v0.1

**Brand · UI · Dot/Halftone · Motion**

기준 원칙: **Dot / Halftone은 스타일이 아니라 기억과 창작 과정의 상태를 보여주는 Product Language다.**
판단 규칙: 도트가 **어떤 상태를 말하는지** 한 문장으로 설명할 수 없으면 쓰지 않는다.

연결 문서: `MUMUMONG_PDR_v0.1.md`. 화면 ID(S01~S16)와 엔진 상태는 PDR을 따른다.

---

## 1. Visual Identity Summary

무무몽은 꿈속이 아니라 **깨어난 아침의 책상**에서 쓰는 앱이다.

- 화면은 흰 종이, 검은 활자, 넓은 여백으로 조용하게 유지한다.
- 꿈과 기억이 **형태를 얻는 순간**에만 도트가 모이고, 새벽빛 같은 스카이블루가 잠깐 살아났다가 다시 잉크로 가라앉는다.
- 완성된 책조차 완전히 선명해지지 않는다. 경계에 잔상이 남는다.

```
White Editorial (평상시)  ──반응──▶  Dot + Sky (상태 변화)  ──정착──▶  White Editorial (+ 남은 잔상)
```

**핵심 문장:** "A dream takes form, but never fully wakes." / "형태를 얻지만, 완전히 깨어나지는 않는다."

## 2. Brand Keywords

키워드는 반드시 **아닌 것**과 짝을 이룬다. 그래야 판단 기준으로 쓸 수 있다.

| 키워드 | 이다 | 아니다 |
|---|---|---|
| **Forming (형태를 얻는)** | 조각이 모여 윤곽이 생기는 과정 | 흐린 것이 선명해지는 보정, 해석과 해독 |
| **Lingering (잔상)** | 완성 후에도 남는 도트, 비어 있는 영역 | 뿌옇게 번진 블러, 저해상도 |
| **Quiet (조용한)** | 반응할 때까지 기다리는 화면 | 텅 비고 무심한 화면 |
| **Manuscript (원고)** | 페이지, 활자, 메타데이터, 판권면 | 카드와 위젯이 나열된 앱 대시보드 |
| **Morning (아침의)** | 흐린 하늘, 창가의 빛, 종이 | 밤하늘, 달, 별, 우주, 보라 |

| `ink` (night) | `#E8E5DF` |

- 적용 범위: Reader, 원고 홈. 시스템 다크 모드를 따르거나, 21시 이후 자동 전환(설정 가능).
- 보라, 남색, 그라데이션 배경은 금지한다. Night Paper는 **어두운 종이**이지 밤하늘이 아니다.

`bg.base` `bg.raised` `bg.subtle` `text.primary` `text.secondary` `text.meta` `border.hairline` `focus.ring` `state.selected.bg` `state.new.dot` `state.new.mark` `dot.ink` `dot.new` `dot.stray`

### 3.4 스카이블루 사용 규칙

1. **텍스트 색으로 쓰지 않는다.** 대비가 부족하다. 링크와 강조도 잉크로 처리한다.
2. **정상 상태에서는 화면 면적의 3% 이하.** 반응 순간에는 최대 15%까지 허용하고, 1.5초 안에 3% 이하로 되돌아온다.
3. 스카이는 항상 **"방금 생긴 것"**을 뜻한다. 새 도트, 새 문단 표시, 진척 증가분, 녹음 중 상태가 여기에 해당한다. 오래된 것은 반드시 잉크로 가라앉는다.
4. 버튼 채움색으로 쓰지 않는다. 주 CTA는 `ink` 채움에 `paper` 텍스트다.

## 4. Typography Direction

### 4.1 서체

| 역할 | 서체 | 이유 |
|---|---|---|
| 읽기 본문, 제목, 표지 | **마루 부리 (MaruBuri)** | 현대적인 한글 부리. 명조의 고전성보다 동시대 독립출판물에 가깝다 |
| UI, 내비게이션, 버튼 | **Pretendard** | 한글 UI 표준. 부리와 역할이 명확히 갈린다 |
| 메타데이터 | **Pretendard, tabular 숫자 (`tnum`)** | 고정폭 서체를 쓰지 않는다 (§16 참고). 숫자 정렬은 tnum으로 해결 |

- 둘 다 OFL 계열이다. 출시 전 라이선스 파일을 재확인하고 앱 번들 포함 조건을 점검한다.
- 서체는 이 두 개로 끝낸다. 세 번째 서체를 추가하지 않는다.

### 4.2 타입 스케일 (pt / line-height)

| 토큰 | 서체 | 크기/행간 | 용도 |
|---|---|---|---|
| `display.cover` | 마루 부리 Bold | 40 / 1.15 | 볼륨 제목 (표지, 완결) |
| `display.title` | 마루 부리 Bold | 28 / 1.25 | 원고 홈 볼륨 제목 |
| `title.scene` | 마루 부리 Regular | 21 / 1.4 | 장면·장 제목 |
| `body.read` | 마루 부리 Regular | **18 / 1.8** | 원고 본문 (한글 부리는 행간을 넉넉히) |
| `body.read.s` | 마루 부리 Regular | 16 / 1.75 | 출처 시트의 원문 발췌 |
| `body.ui` | Pretendard Regular | 15 / 1.5 | 설명, 입력 |
| `label` | Pretendard Medium | 13 / 1.4 | 버튼, 칩, 탭 |
| `meta` | Pretendard Medium, tnum | 11 / 1.4, 자간 +0.04em | VOL, DREAM, 날짜, 쪽수 |

### 4.3 한글 조판 규칙

- **줄바꿈:** `word-break: keep-all` (Flutter는 단어 단위 줄바꿈 처리). 어절이 중간에 쪼개지지 않게 한다.
- **정렬:**
  - 앱 본문은 **왼쪽 정렬(ragged)**. 모바일에서 keep-all과 양쪽 정렬을 함께 쓰면 자간이 벌어진다.
  - PDF는 양쪽 정렬로 조판한다.
- **문단 구분:** **첫 줄 들여쓰기 1em, 문단 사이 간격 없음.** 책 조판을 따른다. 장면 전환은 여백 2행에 도트 1개로 표시한다.
- **한 줄 길이:** 한글 26~34자. 모바일 좌우 여백 24pt에서 18pt로 조판하면 자연히 맞는다.
- **부호:** 따옴표는 “ ” ‘ ’, 말줄임표는 …(한 글자), 대시는 —.
- **대문자:** Latin 대문자는 **코드성 식별자에만** 쓴다 (VOL.01, DREAM 014). 라벨, 버튼, 섹션 제목에 대문자 트래킹을 쓰지 않는다.

### 4.4 메타데이터를 디자인 요소로

```
VOL.01        DREAM 014        SEP 11 2026
```

- 구분은 **간격(≥16pt)**으로 한다. 가운뎃점(·)을 남발하지 않는다.
- 위치는 항상 같다. 화면 최상단 좌측이 볼륨, 우측이 날짜와 쪽수다. 위치의 일관성이 곧 "책의 러닝 헤더"라는 인상을 만든다.
- 숫자는 3자리 제로 패딩(`DREAM 014`)으로 원고 번호처럼 보이게 한다.

## 5. Logo Direction

### 5.1 개념

로고 전체를 하프톤으로 만들지 않는다. **원(○) 하나만 도트 상태**로 둔다.
- Latin 워드마크: **MUMUMONG의 O**
- 한글 워드마크: **몽의 받침 ㅇ**

두 체계 모두에서 같은 원이 도트가 된다. 이것이 로고의 유일한 장식이다. 의미는 "하나의 꿈이 형태를 얻는 중"이다.

```
MUMUM●NG          무무모
                    ◉   ← 몽의 받침 ㅇ이 하프톤 원
(●: 하프톤 원, 중심은 조밀하고 가장자리로 갈수록 성기며 테두리 밖으로 도트 2~4개가 흩어짐)
```

### 5.2 워드마크 규칙

- **Latin:** 기하학적 산세리프 대문자, 굵기 Medium, 자간 +0.02em. 로고는 산세리프로 두고, 에디토리얼 인상은 본문 부리가 맡는다. 역할을 분리하는 것이다.
- **하프톤 원:** 정사각 격자 5×5~7×7 셀. 중심 도트 반지름 100%에서 외곽 35%까지 줄어든다. 원 바깥 **스트레이 도트 2~4개**를 두는데, 위치는 고정한다 (시드 고정).
- **최소 크기:**
  - 24px 미만에서는 하프톤 원을 **솔리드 원 + 스트레이 도트 1개**로 대체한다. 하프톤은 작은 크기에서 뭉개진다.
  - 16px 미만에서는 스트레이 도트도 제거한다.
- **색:** `ink` 단색이 기본이다. 스트레이 도트 1개만 `sky-500`로 두는 변형은 스플래시와 모션에서만 쓴다.

### 5.3 심볼 / 앱 아이콘

- `paper` 배경 위에 하프톤 원 하나. 원은 우측 하단으로 약간 치우치고, 좌상단 방향으로 도트가 흩어진다.
- 스카이 도트는 1개만 둔다. 홈 화면 수십 개 아이콘 사이에서 **유일하게 흰색에 가까운 아이콘**이 되는 것 자체가 차별점이다.
- 금지: 원을 달로 읽히게 하는 초승달 형태, 별 모양 스트레이 도트.

### 5.4 모션 로고 (스플래시, 1.6초)

| 시간 | 동작 |
|---|---|
| 0~400ms | 화면 전체에 성긴 도트 약 120개가 느리게 떠 있다 (Vague) |
| 400~1100ms | 도트가 글자 형태의 마스크 위치로 이동한다. 이징은 `ease.form` |
| 1100~1400ms | 글자는 솔리드로 전환되고, O(또는 ㅇ)만 하프톤으로 남는다 |
| 1400~1600ms | 스트레이 도트 2~4개가 원 밖으로 **아주 조금 밀려난 채 멈춘다.** 완전히 고정되지 않은 상태로 끝낸다 |

## 6. Dot / Halftone Graphic System

### 6.1 구성 요소

| 파라미터 | 의미 | 기본값 |
|---|---|---|
| `cell` | 격자 셀 크기 | 6pt (커버), 4pt (소형), 10pt (스플래시·키비주얼) |
| `grid` | 격자 형태 | 정사각. 인쇄 하프톤의 45° 회전은 표지에서만 |
| `radius` | 도트 반지름 | 0 ~ 0.4 × cell. 마스크 농도와 clarity로 결정 |
| `jitter` | 격자 이탈 | ±0.15 × cell × (1 − clarity) |
| `dropout` | 형상 내 도트 탈락 확률 | 0.12 + 0.6 × (1 − clarity). **최소값 0.12, 절대 0이 되지 않음** |
| `stray` | 형상 밖 떠도는 도트 비율 | 셀의 약 2% (clarity 0.9) ~ 5.5% (clarity 0) |
| `clarity` | 형태를 얻은 정도 | 0.0 ~ **0.9 (상한, 하드 코딩)** |
| `mask` | 형상 소스 | 모티프 그레이스케일 이미지 (sharp + blur 2종) |
| `seed` | 도트 배치 시드 | 볼륨마다 고정. 같은 볼륨은 언제 봐도 같은 도트 |

**`clarity.max = 0.9`는 디자인 시스템의 헌법이다.** "Clearer, but never completely clear."를 코드로 강제하는 값이다. 어떤 화면, 어떤 완결 상태에서도 0.9를 넘기지 않는다.

### 6.2 두 가지 렌더러

| 렌더러 | 용도 | 구현 |
|---|---|---|
| **Field (셰이더)** | 커버, 진척, 완결 리빌, 키비주얼 | Flutter `FragmentProgram` (GLSL). 마스크 텍스처와 clarity 유니폼으로 정적·저빈도 변화 표현 |
| **Particles (페인터)** | 기록 입력, 처리 중, 신규 도트의 이동 | `CustomPainter`, 최대 1,500개. 개별 이동과 합류 표현 |

- 두 렌더러를 전환할 때: 파티클이 목적지(필드의 셀 중심)에 도착하면 사라지고, 필드의 해당 셀이 켜진다. 사용자에게는 **도트가 표지 안으로 들어가 박힌 것**처럼 보여야 한다.

### 6.3 커버 셰이더 (개념 코드)

```glsl
#include <flutter/runtime_effect.glsl>

uniform vec2  uSize;       // 캔버스 px
uniform float uCell;       // 셀 px (기본 6*dpr)
uniform float uClarity;    // 0.0 ~ 0.9
uniform float uTick;       // 반응 구간에서만 증가, 평상시 고정 → 정지 화면
uniform float uSeed;       // 볼륨 고정 시드
uniform vec4  uInk;        // premultiplied
uniform sampler2D uMask;   // 모티프 (어두울수록 형상)
uniform sampler2D uMaskBlur; // 같은 모티프의 강한 블러본

out vec4 fragColor;

float hash(vec2 p) { return fract(sin(dot(p, vec2(127.1, 311.7)) + uSeed) * 43758.5453); }

void main() {
  vec2 p = FlutterFragCoord().xy;
  vec2 cell = floor(p / uCell);
  vec2 jit = (vec2(hash(cell + 1.7), hash(cell + 9.3)) - 0.5) * 0.3 * uCell * (1.0 - uClarity);
  vec2 c = (cell + 0.5) * uCell + jit;
  vec2 uv = clamp(c / uSize, 0.0, 1.0);

  // 낮은 clarity: 블러 마스크(뭉친 덩어리) → 높은 clarity: 선명 마스크(윤곽)
  float shape = 1.0 - mix(texture(uMaskBlur, uv).r, texture(uMask, uv).r, uClarity);

  float dropout = 0.12 + 0.6 * (1.0 - uClarity);            // 절대 0이 되지 않음
  float keep = step(dropout, hash(cell + floor(uTick)));
  float stray = step(0.945 + 0.04 * uClarity, hash(cell * 1.31 + 4.2));

  float amt = max(shape * keep * mix(0.35, 1.0, uClarity), stray * 0.3);
  float r = 0.4 * uCell * sqrt(amt);
  float a = (1.0 - smoothstep(r - 0.75, r + 0.75, length(p - c))) * step(0.01, r);
  fragColor = uInk * a;
}
```

- 신규 도트(스카이)는 셰이더가 아니라 **오버레이 파티클 레이어**로 그린 뒤 잉크로 페이드한다.
- 저사양 폴백: 볼륨의 현재 clarity로 커버를 PNG 캐시로 만들고 정적으로 표시한다.

## 7. Dot 상태 단계 정의

**Vague → Fragment → Form → Presence.** "선명해진다"가 아니라 "형태를 얻는다"의 단계다.

| 상태 | clarity | 시각 | 제품 상태 매핑 |
|---|---|---|---|
| **S0 Vague** | 0.00~0.15 | 성긴 도트가 흩어져 있다. 밀도 2~5%, 크기 편차가 크고 격자에 붙지 않는다. 형상 없음 | 볼륨 생성 직후, 기록 시작 순간, 빈 VOL.02 |
| **S1 Fragment** | 0.15~0.45 | 블러 마스크 기반의 **덩어리 2~4개**가 생긴다. 무엇인지 알 수 없다. 격자에 30% 정도 붙는다 | 진척 0~40%, 처리 중 "꿈을 읽는 중" |
| **S2 Form** | 0.45~0.75 | 선명 마스크가 우세해진다. **윤곽을 알아볼 수 있다** (문, 의자, 손…). 가장자리 탈락이 많고 스트레이 도트가 존재한다 | 진척 40~90%, 처리 중 "장면을 쓰는 중" |
| **S3 Presence** | 0.75~**0.90** | 형상이 가장 많이 드러나지만 탈락 12% 이상, 스트레이 도트, 비어 있는 영역이 **항상 남는다** | 완결 가능 이후, 완결 표지 |

**진척 → clarity 매핑 (커버):**
- `clarity = 0.10 + 0.70 × progress` (progress 0~1이면 0.10~0.80)
- 완결 리빌에서만 0.80 → 0.90으로 전환한다.
- 진척 100%와 완결 사이에 **0.1의 여백**이 남는다. 이 마지막 한 단계는 "완성하기"를 눌러야 얻을 수 있는 보상이다.

## 8. Motion / Interaction Principles

### 8.1 Quiet → Reactive → Quiet 규칙

1. **반응은 사용자 행동이나 실제 시스템 상태 변화에만 한다.** 시간이 흘렀다는 이유로 움직이는 장식 모션은 없다. 원고 홈의 표지는 평상시 **완전히 정지**해 있다 (`uTick` 고정).
2. **한 화면에 반응 순간은 하나.** 도트, 스카이, 햅틱이 동시에 여러 곳에서 터지지 않는다.
3. **반응 구간은 3초를 넘기지 않는다.** 처리 중 대기는 예외인데, 대기 중에도 **느리게** 움직일 뿐 계속 반응 강도를 유지하지는 않는다.
4. **정착 후에는 흔적이 남는다.** 반응이 끝나도 새로 생긴 것(도트, 문단 표시)은 잉크로 가라앉아 남는다. 아무 일도 없었던 것처럼 원상 복귀하지 않는다.
5. **반응 모션은 무엇이 바뀌었는지를 보여줘야 한다.** 모션을 빼도 변화가 전달된다면 그 모션은 장식이다. 삭제한다.

### 8.2 모션 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `dur.micro` | 120ms | 칩 선택, 토글 |
| `dur.base` | 240ms | 시트 열림, 상태 전환 |
| `dur.page` | 420ms | 화면 전환, 장면 전환 |
| `dur.settle` | 1500ms | 스카이 → 잉크 가라앉음 |
| `dur.reveal` | 2400ms | 완결 표지 리빌 본 구간 |
| `ease.enter` | cubic-bezier(0.22, 1, 0.36, 1) | 등장, 시트 |
| `ease.page` | cubic-bezier(0.65, 0, 0.35, 1) | 페이지 전환 |
| `ease.form` | cubic-bezier(0.33, 0, 0.15, 1) | 도트 합류 (느리게 출발해 부드럽게 멈춤) |
| `ease.drift` | linear + 저주파 노이즈 | 떠도는 도트 |

- **금지:** 바운스, 스프링 오버슈트, 회전, 스케일 팝, 스켈레톤 시머, 스피너. 무무몽의 기다림은 스피너가 아니라 도트다.
- **햅틱:** 저장 시 `lightImpact` 1회, 완결 리빌 정점에서 `mediumImpact` 1회. 그 외에는 없다.
- **접근성:** OS의 "동작 줄이기"가 켜져 있으면 모든 도트 이동을 `dur.base` 크로스페이드로 대체한다. 정보(단계 라벨, 진척 Δ)는 텍스트로 동일하게 전달한다.

### 8.3 화면 전환

- 원고(S03) → Reader(S08): 표지가 위로 밀려나며 본문 첫 페이지가 올라온다 (`dur.page`). 책을 여는 느낌을 **스케일이 아니라 위치 이동**으로 낸다.
- 장면 간 이동: 도트 구분자 1개가 페이드된다. 페이지 넘김 효과(page curl)는 쓰지 않는다.

## 9. Dream Capture Motion (S04)

**의미:** 말하거나 쓸수록 흩어진 기억이 **재료로 쌓인다.**

| 입력 | 도트 반응 |
|---|---|
| 녹음 시작 | 화면 하단 1/3에 S0 Vague 도트 약 20개가 `dur.base`로 나타난다. 녹음 표시는 `sky-500` 도트 1개가 호흡하듯 깜빡인다 (0.5Hz, 녹음 중인 동안만) |
| 음성 입력 중 | 음량 RMS에 비례해 도트를 생성한다 (초당 최대 12개). 새 도트는 `sky-300`로 태어나 `dur.settle` 후 잉크가 된다. 위로 느리게 떠오른다 (`ease.drift`, 20pt/s 이하) |
| 텍스트 입력 중 | **어절 1개당 도트 1개** 생성. 글자마다 생성하면 과하다 |
| 입력 멈춤 2초 이상 | 생성 중단. 도트는 제자리에서 미세하게 떠 있다 |
| 누적 | 도트 수는 입력량에 비례하되 최대 300개. 이후에는 새 도트 대신 기존 도트가 커진다 (밀도로 표현) |
| **저장** | 모든 도트가 `ease.form`으로 한 점에 모인 뒤 → 작은 클러스터가 되어 → 화면 상단(원고 방향)으로 빠져나간다. `dur.page`. 햅틱 1회 |

- 텍스트 입력 영역에는 도트를 **절대 겹치지 않는다.** 도트는 입력 영역 바깥, 하단 여백에만 존재한다.
- 목적은 잠결의 사용자에게 "지금 남기고 있다"는 피드백을 **읽지 않아도** 주는 것이다.

## 10. AI Processing Motion (S06)

**의미:** 기억의 조각이 원고의 문장이 되는 과정. 도트는 **실제 파이프라인 단계와 실제 데이터에 연동**한다. 가짜 진행 연출은 금지한다.

| 파이프라인 (`jobs.type`) | 단계 라벨 (`meta` 스타일) | 도트 동작 | 데이터 연동 |
|---|---|---|---|
| extract | 꿈을 읽는 중 | 기록 화면에서 넘어온 클러스터가 퍼지면서 **덩어리 N개**로 나뉜다 (S1) | **N = 추출된 elements 수** (최대 8) |
| link | 이어질 곳을 찾는 중 | 화면 위쪽에 원고 표지의 흐린 필드가 나타나고, 덩어리 일부가 그쪽으로 끌려간다 | 매칭된 엔티티 수만큼 덩어리가 이동 |
| plan · write | 장면을 쓰는 중 | 덩어리가 풀리며 도트가 **가로 줄**로 정렬된다. 도트가 활자 행처럼 보이는 상태 | 줄 수 ≈ 예상 문단 수 |
| validate | 확인하는 중 | 줄이 정지하고 좌→우로 한 번 훑는 밝기 변화 | — |
| commit | — | 도트 줄이 **실제 텍스트 행으로 크로스페이드**되며 S07 리빌로 전환 | — |

- 라벨은 화면 좌상단에 메타 스타일로 표시하고 `jobs.status`를 따른다. 단계가 넘어갈 때 라벨만 교체한다 (`dur.base`).
- **대기가 20초를 넘으면:** 도트 속도를 절반으로 줄이고, 하단에 "다른 일을 하셔도 돼요. 완성되면 알려드릴게요."를 표시한다.
- **실패하면:** 도트가 흩어져 S0로 돌아간다. 라벨은 "장면을 만들지 못했어요. 꿈은 보관함에 저장되어 있어요."로 바꾸고 [다시 시도] 버튼을 둔다. 사과하지 않고, 무엇이 안전한지 먼저 말한다.

## 11. Manuscript Progress Visual (S03)

### 11.1 원고 홈 레이아웃

```
┌──────────────────────────────────┐
│ VOL.01                 SEP 11 2026 │  ← meta, 러닝 헤더
│                                    │
│                                    │
│         ░░▒▒▓▓█▓▒░                 │
│       ░▒▓██████▓▒░    ·            │  ← 도트 커버 (Field 렌더러)
│        ▒▓█▓▒ ▒▓█▒                  │     종횡비 2:3 (책 비율)
│    ·    ░▒▓▓▒▒▓▒░                  │     폭 = 화면폭 − 48pt
│           ░░▒░        ·            │
│                                    │
│ 이름 없는 원고                  42% │  ← display.title / meta
│ 7 dreams   11 scenes   약 35p      │  ← meta
│ 오늘  새 장면 1   연결 1   +6%       │  ← Δ 라인 (조건부)
│ ─────────────────────────────────  │
│ 미스터리와 초현실의 성격이 보여요     │  ← 장르 태그 (조건부)
│                                    │
│ [ 꿈 기록하기 ]      이어 읽기       │  ← 아침엔 기록이 주 CTA, 밤엔 이어 읽기
└──────────────────────────────────┘
```

- **제목 전 상태:** 완결 전 볼륨의 제목 자리에는 "이름 없는 원고"를 둔다. 제목은 완결 때 붙인다. 이름 없는 상태도 원고의 한 상태로 보여준다.
- **% 숫자:** 우측 정렬, tnum. 원형 게이지나 막대 게이지는 쓰지 않는다. **표지의 도트 밀도가 곧 게이지다.**

### 11.2 성장 순간 (S07 리빌 → S03 복귀 시 1회)

| 시간 | 동작 |
|---|---|
| 0ms | 표지가 이전 clarity로 표시된다 |
| 200~1100ms | 이번 꿈의 MU에 비례한 신규 도트(`sky-300`, 20~120개)가 표지 바깥에서 들어와 빈 셀에 박힌다 (Particles → Field 전환) |
| 1100~1500ms | clarity가 새 값으로 보간된다. 윤곽이 조금 더 드러난다 |
| 1500~3000ms | 신규 도트가 `sky-300` → `ink`로 가라앉는다 (`dur.settle`). Δ 라인 숫자가 카운트업된다 |
| 3000ms~ | 정지 |

- 같은 성장은 **한 번만** 재생한다. 다시 방문했을 때는 정적인 결과만 보여준다.
- 진척이 감소한 경우(사용자가 뺀 경우): 해당 도트가 페이드아웃된다. 스카이를 쓰지 않는다. 스카이는 "생긴 것"에만 쓰기 때문이다.

## 12. Completion / Cover Reveal Interaction (S14e)

**의미:** 한 권이 **잠시 형태를 얻는** 순간. 끝이 아니다.

| 시간 | 동작 |
|---|---|
| 0~400ms | UI 크롬(탭, 버튼)이 페이드아웃된다. `paper` 위에 표지만 남는다 (clarity 0.80) |
| 400~1000ms | 모든 도트가 미세하게 떨린다 (`uTick` 증가, 반응 구간 시작) |
| 1000~3400ms | clarity 0.80 → **0.90** (`ease.form`). 스트레이 도트는 바깥으로 약간 밀려나고, 이 볼륨에서 가장 최근에 생긴 도트들이 한 번 `sky-500`로 빛났다가 가라앉는다 |
| 3400ms | **정점.** 햅틱 `mediumImpact`. 도트 정지 |
| 3400~4200ms | 표지 아래 제목이 `display.cover`로 조판된다 (페이드와 8pt 상승). 그 아래 메타 `VOL.01   COMPLETE   {날짜}` |
| 4200~5400ms | 판권면 한 줄: "이 책의 문장 중 68%는 당신의 꿈에서 왔습니다." |
| 6600ms~ | 화면 최하단에 **S0 Vague 도트 약 30개**가 아주 흐리게 나타나고 "다음 꿈에서 VOL.02가 시작됩니다." 표시 |

- 탭하면 즉시 스킵된다 (최종 상태로 점프). 두 번째 이후 열람 시에는 재생하지 않는다.
- 금지: 폭죽, 컨페티, 트로피, 축하 이모지. 무무몽의 보상은 **표지가 드러나는 것 자체**다.

## 13. Key Visual Direction

### 13.1 원칙

- 소재는 **현실의 사물과 공간**이다. 문, 복도, 의자, 손, 창, 계단, 나무, 건물, 우산, 엘리베이터, 전화기, 신발.
- 한 이미지에 **사물 하나.** 중심에서 약간 벗어나게 배치하고, 여백은 30~50%.
- 사람은 **실루엣이나 신체 일부(손, 뒷모습)**로만 쓴다. 얼굴은 쓰지 않는다. 얼굴은 특정 인물로 읽히고, 꿈 속 인물은 늘 불확실하기 때문이다.
- 형상의 20~40%는 탈락 영역으로 둔다. 탈락은 **무작위 노이즈가 아니라 한쪽 방향으로 흩어지는 형태**가 좋다. 기억이 한쪽에서부터 새어 나가는 느낌이다.

### 13.2 MVP 표지 = 모티프 라이브러리 (AI 이미지 생성 없음)

MVP에서는 AI 이미지 생성을 쓰지 않는다. 대신 볼륨마다 고유한 표지를 만드는 방법:

1. 모티프 그레이스케일 마스크 **24종**을 제작한다. 사진이나 3D 렌더 → 흑백 → 대비 커브 → 1024px, sharp와 blur 두 가지 버전.
2. 엔진의 E7에서 볼륨의 **최다 등장 object·place 엔티티**를 모티프 태그로 매핑한다 ("붉은 우산" → `umbrella`).
3. 매핑된 마스크, 볼륨 시드, clarity를 조합하면 같은 모티프라도 볼륨마다 다른 도트 배치가 나온다.
4. 모티프는 장면 5개 이후에 확정한다. 그 전에는 추상 필드(S0~S1)만 보여준다. 표지는 **꿈이 쌓여야** 무엇인지 드러난다.
5. 매핑이 실패하면 `door` 기본 모티프를 쓴다.

**모티프 24종 (초안):** door, corridor, stairs, elevator, window, chair, table, bed, hand, back_figure, umbrella, phone, shoe, key, tree, sea_horizon, building, bridge, room_corner, bus_seat, school_desk, mirror, lamp, road

- 제외: moon, star, cloud, eye, feather, mask. 꿈 앱 클리셰이거나 신비주의로 읽히는 것들이다.

### 13.3 마케팅 키비주얼

- 동일한 원칙을 대형으로 쓴다: `cell` 10pt, 한 사물, 넓은 여백, 한쪽 가장자리의 탈락.
- 카피는 마루 부리로 조판한다. 이미지 위에 겹치지 않고 **여백에 배치**한다.

## 14. Dot 사용처 / 금지처

| 사용한다 (상태를 말할 때) | 말하는 상태 |
|---|---|
| 기록 화면 하단 여백 | 기억이 재료로 쌓이는 중 |
| 처리 화면 | 조각이 문장이 되는 중 (실제 단계와 연동) |
| 원고 홈 표지 | 원고가 얼마나 형태를 얻었는가 |
| 리빌 새 문단 좌측 여백 | 방금 원고에 들어온 문장 (스카이 → 첫 열람 후 잉크) |
| Reader 여백 출처 표시 (토글) | 출처: ● D 꿈 / ○ C 연결 / │ U 내가 씀 |
| 장면 구분자 | 장면이 바뀌었다 (도트 1개) |
| 보관함 clarity 표시 | 그 꿈이 얼마나 생생했나 (도트 1~3개) |
| 완결 리빌, 완성본 표지, 로고, 스플래시 | 형태를 얻은 상태, 브랜드 |

| 사용하지 않는다 | 이유 |
|---|---|
| 본문 텍스트 위나 뒤 (배경 텍스처 포함) | 가독성. 원고는 활자가 주인공 |
| 편집 모드 | 쓰는 중에는 조용해야 한다 |
| 설정, 계정, 권한 요청, 법적 고지 | 상태를 말할 것이 없다 |
| 버튼, 칩, 탭 아이콘의 장식 | 장식이 되는 순간 언어로서의 힘을 잃는다 |
| 작은 로딩 (1초 미만 동작) | 도트는 의미 있는 기다림에만 쓴다. 짧은 동작은 즉시 반응 |
| 에러, 빈 상태 일러스트 | 빈 상태는 텍스트로 행동을 안내한다 (단, VOL.02 빈 필드는 예외: "아직 형태가 없음"이라는 상태 자체) |
| 알림·스토어 스크린샷의 배경 채움 | 도트가 흔해지면 표지의 가치가 떨어진다 |

## 15. Editorial Layout Principles

### 15.1 그리드

- 기본 단위 4pt. 좌우 여백 24pt. 본문 컬럼은 단일 컬럼.
- 위계는 **박스가 아니라 활자의 크기, 굵기, 여백**으로 만든다. 카드, 그림자, 둥근 컨테이너를 쓰지 않는다.
- **radius 규칙:** 입력 필드와 시트 상단은 12pt, 칩은 999pt, 버튼은 0pt (종이에 인쇄된 라벨처럼). 모든 요소에 같은 radius를 쓰지 않는다.
- 구분은 여백을 먼저 쓴다. 헤어라인(`line`, 0.5pt)은 **목록 항목 사이와 러닝 헤더 아래**에만 쓴다.

### 15.2 Reader (S08)

```
┌──────────────────────────────────┐
│ VOL.01   이름 없는 원고        p.23 │  ← 러닝 헤더 (meta), 스크롤 시 유지
│ ───────────────────────────────── │
│                                    │
│ 3                                  │  ← 장면 번호 (실제 순서이므로 번호 사용)
│ 붉은 문                             │  ← title.scene
│                                    │
│ ●   복도는 생각보다 길었다. 발밑의     │  ← body.read, 첫 줄 들여쓰기
│     물은 발목까지 차 있었고…           │     ● = 여백 출처 표시 (토글 ON 시)
│ ○   그 문은 2장에서 본 적 있는        │
│     색이었다.                        │
│                                    │
│                 ·                  │  ← 장면 구분 도트
└──────────────────────────────────┘
```

- 세로 스크롤을 쓴다. 페이지 넘김은 MVP에서 쓰지 않는다. 쪽수 `p.23`는 글자 수 ÷ 700으로 환산해 러닝 헤더에만 표시한다.
- 문단 롱프레스 → 편집, 탭 → 출처 시트. 두 제스처만 쓴다.
- **출처 시트:** 하단에서 올라온다 (`paper-pure`, 상단 radius 12pt). 원문 발췌는 `body.read.s`로 쓰고, 해당 요소는 `sky-100` 배경으로 강조한다.

### 15.3 리빌 (S07)

- 상단은 메타 `DREAM 014 → SCENE 12`. 번호의 흐름이 곧 "꿈이 원고가 됐다"는 메시지다.
- 새 문단은 좌측 여백에 `sky-500` 세로 도트열로 표시한다 (첫 열람 후 잉크).
- 본문이 끝난 아래에 연결 결정 카드를 둔다. 카드도 박스가 아니다. 헤어라인 위아래와 질문(`body.ui`), 선택지 칩 3개로 구성한다.

### 15.4 PDF 조판 (완성본)

- 판형 128×188mm (국내 문고·에세이 판형 계열). 본문 마루 부리 10pt / 행간 175%, 양쪽 정렬, 첫 줄 들여쓰기.
- 구성 순서: 표지(도트 커버 + 제목) → 판권면(날짜, 볼륨, 출처 비율) → 차례 → 본문 → 작가의 말 → 부록 "이 책의 꿈들".
- 장 시작 페이지는 우측 페이지, 상단 1/3 여백 뒤에 장 번호와 제목.

## 16. Design Do / Don't

| Do | Don't |
|---|---|
| 도트는 상태가 바뀔 때만 쓴다 | 배경 텍스처나 장식 패턴으로 쓴다 |
| 완결 표지도 clarity 0.9에서 멈춘다 | 완결 시 사진처럼 선명한 이미지 |
| 스카이는 "방금 생긴 것"에만 쓰고 가라앉힌다 | 스카이 버튼, 스카이 텍스트, 스카이 배경 면 |
| 위계는 활자와 여백으로 만든다 | 둥근 카드와 그림자로 콘텐츠를 잘게 나눈다 |
| 장면 번호처럼 실제 순서에만 번호를 쓴다 | 순서가 아닌 목록에 01 / 02 / 03 장식 |
| Latin 대문자는 코드 식별자에만 쓴다 | 모든 라벨에 대문자와 넓은 자간 |
| 메타는 고정 위치와 간격으로 구분한다 | 모든 메타를 가운뎃점으로 이어 붙인다 |
| 에러는 무엇이 안전하고 무엇을 하면 되는지 말한다 | "앗! 문제가 발생했어요 😢" |
| 현실 사물을 모티프로 쓴다 | 달, 별, 구름, 눈, 깃털, 보라색 그라데이션 |
| 처리 단계는 실제 파이프라인 상태를 보여준다 | 가짜 진행 연출, 무한 스피너 |
| 동작 줄이기 설정을 존중한다 | 모션을 끄면 정보도 사라지는 설계 |

**AI 생성 디자인처럼 보이지 않기 위한 점검.** 에디토리얼 방향은 생성형 디자인이 가장 흔하게 수렴하는 기본값과 겹친다. 크림 배경 + 고대비 세리프 + 헤어라인 신문 레이아웃 + 고정폭 메타 라벨 + 대문자 아이브로우 조합이 그렇다. 무무몽이 이 기본값과 갈라지는 지점은 딱 세 가지이고, 이 셋을 흐리게 만드는 변경은 거절한다.
1. **도트가 상태를 표현한다.** 장식이 아니다.
2. **스카이블루 한 색이 "방금"을 뜻한다.** 포인트 컬러 일반론이 아니다.
3. **메타데이터가 실제 원고 번호다** (DREAM 014 → SCENE 12). 분위기용 라벨이 아니다.
