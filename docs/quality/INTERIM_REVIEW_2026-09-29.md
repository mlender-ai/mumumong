# MUMUMONG 중간 점검 보고서

점검일: 2026-09-29 · 코드 기준: `e5f06bc` / `main`

## 1. 결론

**앱의 기본 사용 흐름과 실제 Groq 생성 연결은 구현돼 있다. 최근 작업은 문장 품질을 비교·검수하는 도구를 만든 것이며, 개선된 작가 모델이나 v11 문장을 운영에 반영한 것은 아니다.**

따라서 “Q-10까지 개발 완료”가 아니라 **“Q-10 비교 준비까지 구현, 실제 기준선·품질 판정은 미완료”**로 판단한다.
주인공 역전, 어색한 도입·제목이 다양한 꿈에서 해결됐다고 인정할 실측 근거는 아직 없다.

이번에는 보고서만 작성했다. 코드 수정, 신규 개발, 모델/API 호출, Supabase 배포, DB 원고 교정, Git 커밋·푸시는 하지 않았다.

## 4. 검증 근거

### 직전 개발에서 실행한 검증

- 평가 도구 **86개**, 엔진 **132개**, Flutter **120개** 테스트 통과.
- Deno format/lint/check, Dart format, 웹 release 빌드 통과.
- 로컬 Flutter analyze는 원본과 동일함을 확인한 ASCII 경로 사본에서 통과했다. 한글 경로 분석기 문제에 대한 우회이며 원본 경로 통과로 표현하지 않는다.
- 합성 기준선·후보 실행은 각각 3단위/6꿈을 완주했다. 합성 실행은 실제 품질 선별 대상에서 거부된다.
- 최신 [GitHub CI](https://github.com/mlender-ai/mumumong/actions/runs/36578672446)는 엔진·Flutter·DB **3개 작업 모두 성공**했다. Flutter analyze/test/web build와 DB 테스트도 포함한다.

### 이번 보고서 작성에서 재확인한 항목

- 코드 기준 `e5f06bc`, 점검 시작 시 작업 트리 변경 없음.
- 위 CI의 커밋 일치와 전체 성공 상태.
- 읽기 전용 preflight: 실제 dev 정본 파일 없음, 실제 reference 정본 파일 없음, 현재 CLI 환경의 Groq/OpenAI/Anthropic 키 모두 미설정.
- 평가 데이터 Git 유출 가드·로그 안전 가드 통과.
- 동결 4파일이 `edfc13c`와 바이트 동일함을 확인.
- 8788 데모 HTTP 200.

단위 테스트·빌드·CI는 **코드 동작의 근거**다. 한국어 문장력, 실제 충실도, 모델 승률, 실측 비용·지연의 근거는 아니다.
이번에는 전체 테스트, iOS 런타임, 실제 클라우드 생성 흐름을 재실행하지 않았다.
`STATUS.md`의 과거 iOS·클라우드 검증 기록과 최신 변경의 검증을 구분해야 한다.

## 5. 현재 실측을 막는 조건

| 필요한 입력/판정 | 현재 상태 | 필요한 조치 |
|---|---|---|
| dev 꿈 30개 | 평가용 정본 파일 없음 | single 18개(clarity 각 6) + sequence 3×4, 총 21판정 단위로 준비 |
| 로컬 평가용 키 | 현재 CLI 3사 키 미설정 | 기준선 Groq·공통 judge OpenAI, 초기 후보 Anthropic 키를 로컬 환경에 설정 |
| 충실도 사람 검수 | 실제 15건 판정 없음 | 실제 생성 후 15건 직접 검수, 12건 이상 일치 확인 |
| 레퍼런스 자료 | 실제 정본 파일 없음 | 양성 25편·대조군 5~8편 직접 수집/라벨, 시점·장르 조건 충족 |
| 작가 모델 블라인드 판정 | 실제 후보 실행 없음 | 자동 생존 후보마다 기준선 대비 21단위 판정, G1 확인 |

“로컬 평가용 키 없음”은 **Supabase 운영 Groq 키가 없다는 뜻이 아니다.** 기존 운영 연결과 로컬 평가 환경은 별개다.
또한 평가 파일이 없다는 것은 앱에 저장된 사용자 꿈이 없다는 뜻이 아니다.
키 값이나 원문을 public Git·콘솔·보고서·채팅에 붙이지 않는다.

## 6. 다음 단계와 개발 제한

1. 실제 dev·로컬 키·공통 judge/후보 설정을 준비한다. 모델과 환경은 측정 전에 고정한다.
2. 실제 Q-04 호출을 확인하고, Q-08 기준선 생성과 Q-07 사람 검수를 완료한다. A/A 10단위는 권장 검사다.
3. Q-09 실제 레퍼런스 프로파일을 확정한다. 원문 자동 수집·LLM 전송은 하지 않는다.
4. Q-10 실제 후보 실행 → 자동 선별 → 사람 판정 → G1 승자/미통과 결론을 기록한다.
5. 운영 반영을 선택하면 Q-11 공급자 고지·재동의·staging 확인·24시간 관측을 거친다. 이후 v11 구조 작업으로 진행한다.

판정이 없다고 “통과 후보 없음”으로 결론 내릴 수 없다. 아직은 **후보 미평가**다.
Q-10 자동 선별 생존도 G1 승자 선정이 아니다.
동결 프롬프트·opening 보조 함수는 유지하며, 생성 원고를 DB에 직접 써서 교정하지 않는다.
holdout은 읽지 않았고 Q-32까지 잠금을 유지한다.

M1의 독립 잔여 항목은 AI 동의/보존 고지, 실기기 인증·STT, 푸시, 완결 상태/UI, PDF, 장기 큐 복구다.
이 보고서는 다음 개발을 승인하거나 자동 착수시키는 문서가 아니다. 중간 점검 지시 전에는 추가 개발하지 않는다.
