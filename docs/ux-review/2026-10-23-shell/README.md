# 홈·보관함·설정의 여백/행동 정렬

2026-10-23 KST. 저장/결과의 v0.9 규격을 탐색 화면에 적용했다. 첫 꿈 저장→새 결과 읽기→다시 기록과 보관함/설정 탐색을 단순화하는 시각 후속 단위다. P4나 첫 꿈 경험 전체 완료를 뜻하지 않는다.

## 변경

- 홈의 큰 표지/빛/오브젝트는 유지한다. 주 행동 폭280px, 내용→행동32px, 보조 행동은 공통15px/400이다. 새 결과의 ‘새 장면 읽기’와 중복되는 ‘이어 읽기’를 함께 쌓지 않고 ‘꿈 기록하기’만 보조로 둔다. 미열람 결과가 없을 때 이어 읽기는 유지한다. 대기 안내는0개 상태를 생략하고 실제 상태만 표시한다.
- 기록만 저장한 첫 꿈이 있으면 홈 제목이 ‘첫 꿈이 남아 있어요’로 전환된다. 브라우저에서 발견한 이전 제목은 원고 진척0만 보고 기록도 없는 것처럼 표현했기 때문이다. 저장/생성 상태를 바꾸지 않고 실제 대기 꿈 유무를 사용한다. 빈 상태/오류 행동은280px/간격32px를 공유한다.
- 보관함/설정은 같은 `MongPageHeader`를 사용한다. 좌우/상단24px, 제목 영역 최소48px, 설명8px, 다음 내용32px. 설정의 반복 영문 헤더를 없애고 설명을 secondaryInk로 올렸다. 그룹24px/행16px/내부4px 리듬을 공유한다.
- 보관함의 고정 제목+별도 목록 스크롤을 하나의 CustomScrollView로 통합했다. 큰 글자에서 제목이 화면을 계속 차지하지 않으며 필터/기록 상세는 그대로다. 상태 태그는 Wrap, 큰 글자의 날짜는 본문 위로 이동한다.
- 홈·목록은 실제 GNB SafeArea와 끝32px 여백을 사용한다. GNB 재질/배경/시스템 색, 처리 Orb, 정적 입력/STT, 저장·생성·Reader·출처·삭제/고지 계약은 변경하지 않는다.

### 발견·보정

최초 새 탐색 테스트는 ‘기록만’ 필터와 행의 같은 텍스트를 구분하지 못했고, 스크롤 직후 paint/비동기 상세 로드를 기다리지 않아 실패했다. 필터를 실제 ChoiceChip으로 지정하고 pump/runAsync 경계를 수정했다. hit-test 경고를 숨기거나 좌표로 우회하지 않았다. 큰 글자에서 날짜의 마지막 글자가 다음 줄로 넘어가는 것은 실제 배치 문제였으며 날짜를 본문 위로 이동해 수정했다.

첫 기록 보관 제목의 신규 검사는 처음에 이미42% 원고가 있는 prototype fixture를 사용해 실패했다. 실제 빈 첫 권을 만든 뒤 기록만 저장하는 fixture로 고쳤다. 진행 중 원고를 첫 기록 상태로 간주하도록 제품 코드를 바꾸지 않았다.
