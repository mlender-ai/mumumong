## 1. 가장 중요한 요약

- 제품은 **꿈 기록 → 분석 → 연결 → 소설 생성 → 사용자 방향 → 원고 성장 → 사용자 완결**의 일곱 단계다. 우선순위는 ‘첫 꿈이 매력적인 첫 작품이 되고, 두 번째 꿈을 기록하고 싶어지는 경험’이다.

- 최근 핵심 작업은 입력/키보드·IndexedDB 보존·PWA 시작 실패 복구·설치 origin 문제, 시작 화면 단순화와 **하나의 Thinking Orb** 통일이다.

## 4. 사용자가 반복해서 강조한 UX

1. 토스처럼 한눈에 이해되고 **화면당 시각적 주 행동 하나**. ‘버튼 한 개’를 이유로 뒤로가기/닫기/필수 탐색을 없애지 않는다. 동급 CTA 여러 개와 카드 대시보드는 피한다.
2. 큰 소개/메인 진입 화면과 움직이는 브랜드 그라디언트는 유지한다. 간결화 요구를 화면 삭제로 해석하지 말 것.
3. 따뜻한 스카이블루·라일락 빛이 흰 canvas로 사라지는 구조, 부드러운 라운드와 선택적 중립 글래스. 파란 불투명 주 버튼·흐릿한 글자·균일한 전면 블러로 되돌리지 않는다.
4. 시스템 배경/상단/하단 GNB가 따로 띠처럼 나뉘지 않아야 한다. SafeArea/PWA origin을 확인하고 화면 밖 OS 영역을 CSS로 숨겼다고 주장하지 않는다.
5. 입력과 음성 전사는 **정적·반응성 우선**. 타이핑/말하기마다 Orb·beam·RMS 장식·부모 전체 rebuild를 추가하지 않는다.
6. Orb는 실제 처리/네트워크 대기에만. 현재는 아래에서 지정한 **Thinking 형태 하나**이며 여러 상태 모양을 돌아가며 보여주면 안 된다.
7. 첫 꿈 입력과 실제 결과가 이어져야 한다. 고정 예시를 실제 생성으로 꾸미지 않는다. 꿈 해석/심리 의미/운세를 제공하지 않는다.
8. 온보딩부터 끝까지 흐름을 확인할 수 있어야 하며, 사용자 보고 버그를 재현·검증한 다음 배포한다. ‘빌드 성공/HTTP200/많은 테스트’만으로 UX 완료라고 하지 않는다.

## 5. 가장 최근에 바뀐 화면 — 되돌리지 말 것

### 설치 안내 제거

- 소개/설정에서 긴 설치 안내로 가던 경로와 `WebInstallGuide`를 제거했다.
- [web/install.html](/Users/cocteau/Documents/무무몽/web/install.html)은 구 링크 호환 진입점만 남긴다. `window.location.replace('/')`로 **같은 origin** 안에서만 첫 화면으로 간다. JS가 꺼지면 짧은 열기 링크가 있다.
- manifest의 `id`, `scope`, `start_url`은 `/`, display는 standalone이다. 계정/저장소/PWA identity를 새로 만들지 않는다.
- 구 preview origin의 HTML/worker가 정식 origin으로 강제 이동하던 것이 브라우저 막대의 확인된 문제 경로였다. 자동 교차 origin 이동을 복원하지 않는다.

### 과거 치명 회귀의 재발 방지

- 웹 전용 안내 행이 나타나거나 사라질 때 unkeyed editor가 재생성돼 iPhone 키보드가 열렸다 닫혔다. 동일 key/FocusNode/EditableText와 한글 IME 조합을 보존한다.

- bootstrap/main/CanvasKit 다운로드 실패 시 흰 화면 대신 명시적 수동 재시도. 같은 배포 CanvasKit을 사용하고 실제 `flutter-first-frame`에서만 HTML 시작 레이어를 제거한다. 활성 editor를 자동 reload하거나 저장소를 지우지 않는다.
- Flutter bootstrap의 serviceWorkerVersion 템플릿을 임의로 따옴표로 감싸지 말 것. SDK 치환 결과를 **컴파일된 JS**에서 문법 검사한다.
